# Fitting and refining a face

How Ductus faces are brought close to a reference glyph by glyph, and the
rules that keep that work safe. The process was built up while making Ductus
Sans; `docs/sans/README.md` sections 19–28 log each round.

## What may be fitted

| Face | Reference | Fitted? | Release status |
|---|---|---|---|
| Ductus Sans (`examples/sans`) | Geist Sans Light / Regular / Bold | yes, glyph by glyph | **open question** (see below) |
| Geist Serif benchmark (`benchmarks/geist_serif`) | Geist Serif Regular | yes, freely | **never**, internal measurement only |
| Ductus Display (`examples/display_serif`) | Geist Serif, as a direction only | pulled toward Geist Serif from iteration 18 at the user's request; since then refined **by eye** only, never with `gfit` | original design |

**Licensing is an open question.** SPEC §8 says anything fitted to a
reference is an internal benchmark and stays in `benchmarks/`. Ductus Sans
is fitted to Geist Sans (shapes, spacing, kerning style) and lives in
`examples/`. Before any release it must either move to `benchmarks/` or
diverge deliberately. HANDOFF §7 tracks this.

- References (SIL OFL) are fetched into git-ignored `reference/` folders
  (`benchmarks/*/fetch_reference.py`).
- They are for measurement and overlays only. Never copy, trace or import
  their outlines. Never commit references, renders of them, or data
  extracted from them (such as Geist's kerning values).
- Fitted values may be committed: font parameters, master JSONs,
  `fitted.yaml`, the benchmark's `spacing.json`, and kerning style
  weights.
- Ductus Display is judged by eye on set words, against its own history
  (`docs/display_serif/`). Do not run `gfit` on it.

## Where values live

- **Regular (default master):** the `kit.params(...)` call in
  `examples/sans/font.py`, plus per-glyph side-bearing deltas in
  `font.spacing`.
- **Weight masters:** `examples/sans/master_bold.json` and
  `master_light.json` (`{"params", "spacing"}`). A master's value
  overrides the weight-scaled default (`kit.weight_master`).
- **Benchmark:** `benchmarks/geist_serif/fitted.yaml` (parameters),
  `spacing.json` (side-bearing deltas) and `kern_style.json` (kerning
  style).
- **Kerning:**
  - sans: `kerning.json`, `kerning_700.json` and `kerning_300.json`;
  - benchmark and display serif: `kerning.json`.

  All are generated by `ductus kern`. Never edit them by hand.

## The loop, per glyph

1. **Rank.** Score every glyph at each weight: IoU, Hausdorff, and the
   location of the worst point (`GlyphScore.worst`). Start with the worst
   Hausdorff, which marks a local defect, then the worst IoU.
2. **Look.** Overlay ours on the reference outline (red) at the best
   offset. Before changing anything, find where the area differs:
   - Measure the XOR regions, the areas where only one outline has ink.
     Overlays can mislead, because the reference is re-aligned for each
     candidate.
   - Render the reference glyph alone when its construction is unclear.
3. **Fit.** `python tools/fitting/gfit.py W GLYPH N [prefixes...]`; see
   below.
4. **Review by eye.** Render before and after, on the reference outline,
   at every weight. Revert anything that is numerically better but looks
   wrong; IoU gains can hide folds, kinks and slivers.
5. **Construction changes.** When a fit stalls, the cause is usually
   structural:
   - **A missing control.** The W borrowed the V's stroke widths, and the
     Æ's diagonal range stopped at 60.
   - **A hard-coded fraction.** The ~'s hump and trough, the brace's
     corner turn.
   - **A shared terminal that spikes when the stroke turns.** The £'s
     hook and the cedilla's end each got their own terminal.
   - **A two-unit overlap that leaves a pinhole.** The f's hook root.

   Add a parameter or a `kit.define` option whose **default reproduces
   the old outline exactly**, so the other faces stay unchanged. Then fit
   it.
6. **Finish the round.**
   - Re-run `ductus kern` at every master.
   - Build the variable font: no glyph may be "held static".
   - Run `ductus test examples/sans/font.py` and `python -m pytest`.
   - Regenerate the sheet and log the round in the face's README.
   - Commit with the exact mean IoU per weight.

## `gfit.py`

```bash
python tools/fitting/gfit.py 400|700|300 GLYPH N [prefix_or_param ...] [--dry] [--wide] [--bench] [--composites]
```

- **Selection.** Parameters are picked by prefix (default `GLYPH_`) or
  by exact name.
- **Search.** Random joint moves on 1–4 parameters, with steps of 4% of
  each range that shrink as the search stalls.
- **Objective.** The mean of IoU − 0.001 × Hausdorff over every glyph
  those parameters touch, so a local bump costs something.
- **Guards.** A candidate is rejected if it changes a contour count, adds
  clustered on-curve points (how folds and kinks show), or fails the
  self-intersection or direction lint.
- **`LOCKED`.** Values set by eye to fix a visible fault cannot be undone
  by a fit, unless named explicitly.
- **Writes.**
  - Weight 700 or 300 updates that master's JSON.
  - Weight 400 writes `font.py`, first **pinning** each master's current
    value of every changed key, so a Regular fit never moves the Light or
    Bold.
- **`--wide`** (masters): extends each range by its width on both sides,
  for offsets that should grow with the stem but are not weight
  parameters. The Bold b/d ovals needed this.
- **`--bench`:** fits the Geist Serif benchmark (400 only, writes
  `fitted.yaml`, no locks).
- **`--composites`:** also scores accented glyphs. Use it for marks: a
  cedilla fitted alone matched Geist's ¸ but worsened ç and Ç.

## When fitting is the wrong tool

- **Plain rectangles** (dashes, _, +, the dieresis dots): measure the
  reference's boxes and set the values directly. The Light dieresis went
  from 0.806 to 1.000 because height and width had to change together.
- **A start far from the target:** scan the glyph's width parameter
  coarsely first. The benchmark A was 922 wide against 759, and only a
  scan got it moving.
- **Shared parameters:** fitting one glyph can move its neighbours, such
  as V and W (stroke widths) or O and Q (the bowl). Re-check them and
  refit their own parameters.
- **Unmerged reference contours:** where the reference overlaps separate
  contours (Geist's Ø slash), its Hausdorff is not meaningful. Judge by
  IoU and by eye.

## Spacing and kerning

- **Sans spacing:** `sb_straight` / `sb_round` plus per-glyph `(dl, dr)`
  in `font.spacing` (`tools/fitting/respace.py` moves them toward the
  reference's).
- **Benchmark spacing:** `tools/fitting/bench_space.py` sets each base
  glyph's side bearings equal to Geist Serif's. Run it twice. Accented
  letters follow their base.
- **Kerning** is optical, measured from our own outlines (`ductus kern`).
  The house style is a per-glyph `[left, right, bias left, bias right]`
  weighting, fitted to the reference's kerning by `kstyle.py`.
  Agreement with the reference on letter pairs:

  | Face | Correlation |
  |---|---|
  | sans | 0.823 |
  | serif benchmark | 0.831 |

  Never copy the reference's kern values themselves.

## Judging by eye (Ductus Display)

- Spacing proofs (nnonoo, HOHOH) and symbol lines at 120–200 px.
- Overshoots against o/O.
- A scan for short steps between curves (2–20 units, outside the serif
  tips), which found the c/e terminal step.
- Spacing that looks open in a small proof may be right at 200 px. Check
  large before changing it.
